# Security policy

## Reporting a vulnerability

Please do not open a public issue for a suspected vulnerability. Contact the repository owner privately through the GitHub security advisory flow or the private contact method listed on the owner's GitHub profile. Include the affected package, reproduction steps, impact, and a safe way to follow up.

Never include tokens, passwords, private keys, or database credentials in a report. Rotate any credential that may have been exposed before submitting details.

## Supported versions

The `main` branch is the only actively maintained development line until the first tagged release. Security fixes will be prioritized for the latest release once releases are published.
